Use SuperPlane to fix one mobile-button issue in a demo application. This walkthrough takes you from a GitHub issue through task refinement and implementation to pull request review.

This guide uses your own copy of the <a href="https://github.com/pixawna/SuperPlane_Demo" target="_blank" rel="noreferrer">SuperPlane Demo repository</a>. You need write access, permission to authorize the GitHub App, and model access as described in the [Quickstart prerequisites](/get-started/quickstart#prerequisites).

The retained images and recordings are illustrative examples of an older flow. Follow the written steps for the current workflow; deployment shown in the overview image is outside this walkthrough.

## What you’ll do

<div class="factory-task-overview">

Keep the homepage buttons from overflowing on narrow screens. Use one GitHub issue titled **Make the home page CTAs fit narrow screens**. The expected result is a focused change that preserves the button text, destinations and keyboard access.

</div>

## 1. Prepare the repository

Open the <a href="https://github.com/pixawna/SuperPlane_Demo" target="_blank" rel="noreferrer">SuperPlane Demo repository</a> and create your own copy. Enable GitHub Issues in your copy if needed. Issues from the original repository are not copied into a fork.

If the mobile-button issue is absent, create it in your repository before onboarding. Describe the homepage buttons, how to reproduce overflow at a narrow viewport such as 320 CSS pixels, and the expected result: all buttons remain visible without horizontal overflow. Ask the agent to preserve their text, links and keyboard access and to run the repository's build and relevant checks. If the current demo no longer reproduces the problem, use a starter revision that does before continuing.

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/images/github_issues_framed.png" alt="SuperPlane Demo repository on GitHub" />
</figure>

## 2. Connect the repository to SuperPlane

Complete the [Quickstart](/get-started/quickstart). Choose GitHub for source control and **GitHub issues** for work intake. Select your copy as both the code repository and backlog repository, confirm its default branch, and use an available hosted model or authorized provider API key.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/videos/superplane_account_setup_1280.gif" alt="Setting up a SuperPlane account and connecting a GitHub repository" />
</figure>

Wait for the initial import and open **Backlog**. Confirm that the mobile-button task links to the issue in your copy. If it is missing, check the import result and intake filters, then import the issue manually from the intake. **Automatic intake** controls later matching events; it is separate from this first import.

## 3. Start the first issue

Open **Backlog** and select **Make the home page CTAs fit narrow screens**. Review its plan and available assessment scores. Scores help assess readiness; they do not guarantee that the agent will succeed.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/videos/superplane_plan_confidence_1280.gif" alt="SuperPlane reviewing a task plan and assessing confidence before implementation" />
</figure>

Refine the task in SuperPlane if the plan lacks the viewport, expected behavior or checks. Use the refinement conversation to add context and review the updated task description. When the scope, repository and expected result are correct, select **Start**. **Auto-start** is off by default; this walkthrough uses manual start.

## 4. Watch the factory implement it

Starting the task moves it into **Implement**. The configured coding agent reads the task and repository instructions, makes the change, and runs the relevant checks. Follow its progress and inspect any setup or execution failure in the task history.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/videos/superplane_start_run_1280.gif" alt="Starting a SuperPlane task and following its progress from Backlog to Implement" />
</figure>

Use the default implementation settings for this first run. You can configure models and execution steps later from the workspace's agent and automation settings.


## 5. Verify the first change

When implementation attaches a pull request, the task waits in **Verify** for review. Open the linked pull request, inspect the diff and check the reported build results and GitHub checks. Run or preview the changed application at the chosen narrow viewport. Confirm that the buttons fit without horizontal overflow and that their text, destinations and keyboard access are preserved.

If a correction is needed, mention `@superplaneagent` with specific feedback on the pull request when the default discussion handler is active. Automatic repair of failed CI checks requires the optional **Fix pull request checks** automation. A passing check alone does not complete the task.

Merge only after the change meets the issue and your review requirements. The default PR Closure automation records completion after the attached pull request is merged. Closing it without merging records a rejected outcome instead.
