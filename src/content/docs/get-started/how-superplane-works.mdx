SuperPlane connects your development tickets, coding agents, source control, continuous integration (CI) and review process into a software factory. Intake imports matching tickets, and Backlog refinement records plans and assessments. Factory lines run tasks with configured agents and checks while your team reviews the result.

The retained images and recordings are illustrative. Use the written instructions and linked guides for the current workflow.

## 1. Import work from your existing tools

SuperPlane connects to the tools where engineering work already lives. Guided setup supports GitHub, Jira and Linear issue intake. Additional supported intakes, such as Sentry, can be added to a workspace. Other integrations need a custom automation to turn their events into tasks.

Each issue becomes a piece of work that SuperPlane tracks from intake through implementation and verification. Your existing tools remain part of the workflow. SuperPlane coordinates them and lets you use your preferred coding agent and model provider.

Read about [Intakes](/intakes/overview) to learn how to choose sources and define which requests enter your backlog.

## 2. Assess which tasks are ready for agents

Before implementation, the Backlog automation can refine the task and repository context into a plan and assessment. Add missing context in the SuperPlane refinement conversation and review the updated description. Scores help assess readiness but do not guarantee success. Use manual **Start** by default; **Auto-start** is a separate configuration choice.

The assessment considers scope, available context and test coverage. It helps your team decide which tasks are ready before an agent starts work.

## 3. Track task progress on one board

See which tasks are waiting, in progress or complete. Each task moves through four stages:

<div class="factory-stage-table">

| Stage | What happens here |
| --- | --- |
| **Backlog** | Tasks are assessed or waiting to start. |
| **Implement** | An agent makes the code change. |
| **Verify** | Status checks and pull request feedback are evaluated. |
| **Done** | The task has completed the factory workflow. |

</div>

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/images/superplane_board_brand.png" alt="SuperPlane board with tasks in Backlog, Implement, Verify and Done" />
</figure>

## 4. Configure agents for each stage

SuperPlane runs agents when their configured automation or refinement flow starts. A board stage is not necessarily a separate agent run. Choose models, instructions, tools and execution steps for the agents your workflow uses.

Use an available hosted model or permitted provider API key during workspace setup. You can select ChatGPT subscriptions for Codex later through [Model sources](/billing/model-sources). Choose available models that match the work each agent needs to do.

## 5. Verify changes and handle failures

After implementation attaches a pull request, the task waits in **Verify** for review. The default GitHub discussion handler responds to human feedback that mentions `@superplaneagent` and to bot feedback. Automatic CI repair requires the optional **Fix pull request checks** automation, with selected checks and an attempt limit. Review the diff and checks before merging; passing checks alone does not complete the task.

</figure>

## 6. Keep people in control of decisions

SuperPlane keeps the start and merge decisions visible. Manual **Start** is the default. Automatic start, additional approval gates and escalation routes depend on configuration; they are not guarantees that the factory detects every decision requiring judgment.

A person remains responsible for accepting uncertain work, reviewing changes and merging the pull request. The default closure automation records completion after merge, or rejection after closure without merge.

<figure class="sp-media-figure sp-media-figure--flush not-content">

</figure>

## Who benefits from SuperPlane?

- **Developers:** Hand off routine fixes. Keep your focus on the hard problems.
- **Engineering teams:** Turn ready backlog tasks into pull requests, with checks and run history attached.
- **Platform teams:** Define the process once. Reuse agent settings and verification rules across repositories.

## Key terms

<dl class="sp-glossary not-content">
  <div>
    <dt>Software factory</dt>
    <dd>The system that coordinates task intake, agent work, verification and human review.</dd>
  </div>
  <div>
    <dt>Intake</dt>
    <dd>The automation that imports matching requests from your existing tools into the backlog.</dd>
  </div>
  <div>
    <dt>Task</dt>
    <dd>One piece of engineering work, with its context, progress and outputs.</dd>
  </div>
  <div>
    <dt>Backlog</dt>
    <dd>Tasks being assessed or waiting for implementation.</dd>
  </div>
  <div>
    <dt>Confidence score</dt>
    <dd>An assessment of whether a task meets your configured criteria, with a reason for the result.</dd>
  </div>
  <div>
    <dt>Stage</dt>
    <dd>A step in the task lifecycle: Backlog, Implement, Verify or Done.</dd>
  </div>
  <div>
    <dt>Agent</dt>
    <dd>The worker that implements changes, fixes failures or prepares pull requests.</dd>
  </div>
  <div>
    <dt>Automation</dt>
    <dd>The rules and actions that run work and decide what happens next.</dd>
  </div>
  <div>
    <dt>Verification</dt>
    <dd>The checks used to decide whether a change is ready for human review.</dd>
  </div>
</dl>
