SuperPlane connects your development tickets, coding agents, source control, continuous integration (CI) and review process into a software factory. Intake automations import matching tickets and record confidence scores. Factory lines then give agents a controlled path to execute approved tasks, apply configured checks and bring your team in when human judgment is needed.

  <img src="https://docs-assets.superplane.com/images/superplane_factory_flow.png" alt="SuperPlane coordinating agents through a software factory workflow" />
</figure>

## 1. Import work from your existing tools

SuperPlane connects to the tools where engineering work already lives. Connect a GitHub repository and issues can appear in the factory backlog without developers copying tasks into another system. You can also assign tasks through Jira and Linear.

Each issue becomes a piece of work that SuperPlane tracks from intake through implementation and verification. Your existing tools remain part of the workflow. SuperPlane coordinates them and lets you use your preferred coding agent and model provider.

Read the [Intakes overview](/intakes/overview) to learn how to choose sources and define which requests enter your backlog.

## 2. Assess which tasks are ready for agents

Before implementation begins the Backlog automation can inspect the task and repository context and report a confidence check. The score and its reason show whether the request has a bounded scope, enough context and an observable success condition. Your routing rule decides whether a task can move forward or must stay visible for the team.

The assessment considers scope, available context and test coverage. It helps your team decide which tasks are ready before an agent starts work.

</figure>

## 3. Track task progress on one board

See which tasks are waiting, in progress or complete. Each task moves through four stages:

<div class="factory-stage-table">

| Stage | What happens here |
| --- | --- |
| **Backlog** | Tasks are assessed or waiting to start. |
| **Implement** | An agent makes the code change. |
| **Verify** | Status checks and pull request feedback are evaluated. |
| **Done** | The task has completed the factory workflow. |

</div>

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/images/whole_board.webp" alt="SuperPlane board with tasks in Backlog, Implement, Verify and Done" />
  <figcaption>The board shows where the task is. The workflow tells SuperPlane how to move it forward.</figcaption>
</figure>

## 4. Configure agents for each stage

When a task enters a stage, SuperPlane runs the agent with the model, instructions, tools and execution steps you define.

Use SuperPlane’s built-in models or connect your own ChatGPT subscription to run Codex. Choose a different model for each stage to match the work it needs to do.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/videos/superplane_models_steps.gif" alt="Configuring models and execution steps for a SuperPlane agent" />
</figure>

## 5. Verify changes and handle failures

After implementation SuperPlane continues working on the result. The Verify stage handles failing status checks and pull request feedback. If something fails that feedback can return to the workflow for another attempt.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/videos/superplane_verification.gif?v=20261103-215257" alt="SuperPlane verifying a change and handling pull request feedback" />
</figure>

## 6. Keep people in control of decisions

SuperPlane does not remove developers from every decision. The factory continues automatically when the outcome is clear and stops when the next step requires judgment.

A person remains responsible for decisions such as accepting uncertain work, reviewing important changes or merging the final pull request.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/images/superplane_human_in_the_loop.png" alt="A person reviewing a decision in the SuperPlane workflow" />
</figure>

## Who benefits from SuperPlane?

- **Developers:** Hand off routine fixes. Keep your focus on the hard problems.
- **Engineering teams:** Turn ready backlog tasks into pull requests, with checks and run history attached.
- **Platform teams:** Define the process once. Reuse agent settings and verification rules across repositories.

## Key terms

<dl class="sp-glossary not-content">
  <div>
    <dt>Software factory</dt>
    <dd>The system that coordinates task intake, agent work, verification and human review.</dd>
  </div>
  <div>
    <dt>Intake</dt>
    <dd>The automation that imports matching requests from your existing tools into the backlog.</dd>
  </div>
  <div>
    <dt>Task</dt>
    <dd>One piece of engineering work, with its context, progress and outputs.</dd>
  </div>
  <div>
    <dt>Backlog</dt>
    <dd>Tasks being assessed or waiting for implementation.</dd>
  </div>
  <div>
    <dt>Confidence score</dt>
    <dd>An assessment of whether a task meets your configured criteria, with a reason for the result.</dd>
  </div>
  <div>
    <dt>Stage</dt>
    <dd>A step in the task lifecycle: Backlog, Implement, Verify or Done.</dd>
  </div>
  <div>
    <dt>Agent</dt>
    <dd>The worker that implements changes, fixes failures or prepares pull requests.</dd>
  </div>
  <div>
    <dt>Automation</dt>
    <dd>The rules and actions that run work and decide what happens next.</dd>
  </div>
  <div>
    <dt>Verification</dt>
    <dd>The checks used to decide whether a change is ready for human review.</dd>
  </div>
</dl>
