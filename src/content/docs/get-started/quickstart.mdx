## Prerequisites

For the smoothest first run have the following ready:

- A [SuperPlane account](https://app.superplane.com/).
- Access to a GitHub repository that you are comfortable connecting.
- Permission to install or authorize the GitHub integration for that repository.
- A repository with a few open issues for SuperPlane to analyze.
- A normal development setup with existing tests or continuous integration (CI) checks.

<div class="sp-first-project-note">
  <Aside type="note" title="NOTE">
    First Software Factory? Choose a repository with small tasks that have a defined outcome.

    Save large architectural changes and work that needs product decisions until you have completed your first factory run.
  </Aside>
</div>

## 1. Create your SuperPlane account

Create your [SuperPlane account](https://app.superplane.com/). The onboarding flow guides you through setting up your workspace and connecting your GitHub repository. Follow the steps below to get started.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/videos/superplane_account_setup_1280.gif" alt="Setting up a SuperPlane account and connecting a GitHub repository" />
</figure>

Need more guidance? Follow [Build your first Factory](/get-started/build-first-factory) for detailed instructions or watch the [Video Walkthrough](/get-started/video-walkthrough) to see the process in action.

## 2. Let SuperPlane prepare the workspace

Connect the repository through GitHub during onboarding. SuperPlane prepares the workspace and begins bringing work into the factory.

Intake will automatically imports your recent GitHub Issues and starts reviewing their suitability for agent execution. You do not need to copy tickets into SuperPlane.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/images/superplane_intake_setup_framed.png" alt="SuperPlane intake setup for bringing work into the factory" />
</figure>

## 3. Open your factory board

Select **Go to your board** to see your tasks across four stages:

<div class="factory-stage-table">

| Stage | What happens |
| --- | --- |
| **Backlog** | Incoming tasks are assessed and wait to start. |
| **Implement** | An agent plans and makes the code changes. |
| **Verify** | Checks and pull request feedback help validate the changes. |
| **Done** | The task has completed the factory workflow. |

</div>

Start with **Backlog**. This is where you’ll find imported tasks before an agent begins work.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/images/superplane_board_framed.png" alt="SuperPlane factory board with tasks waiting in Backlog" />
</figure>

## 4. Understand what happens next

When you start a task it moves through implementation and verification. A failed check can return the task to the agent with feedback. Work reaches Done when the completion rule is satisfied, such as attaching a pull request after every required status check passes.

<figure class="sp-media-figure sp-media-figure--flush not-content">
  <img src="https://docs-assets.superplane.com/images/superplane_task_flow.png" alt="Factory flow from Backlog through Implement and Verify to a review ready pull request" />
</figure>

Congratulations, you created your first software factory. Have questions or want to see the complete workflow? Follow the [guided walkthrough](/get-started/video-walkthrough).

## Tips for your first run

- **Start small:** Choose a focused task with a defined expected outcome.
- **Add enough context:** Describe what should change, where it should change and what success looks like.
- **Choose the right repository:** Use one with a few open issues and existing tests or CI checks.
- **Use the defaults first:** Complete the first run before you change agents, automations or verification steps.
