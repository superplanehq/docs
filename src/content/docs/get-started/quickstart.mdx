## Prerequisites

For the smoothest first run have the following ready:

- A [SuperPlane account](https://app.superplane.com/).
- Access to a GitHub repository that you are comfortable connecting.
- Permission to install or authorize the GitHub integration for that repository.
- A repository with a few open issues for SuperPlane to analyze.
- A normal development setup with existing tests or continuous integration (CI) checks.

<div class="sp-callout not-content">

## 1. Create a SuperPlane account

[Sign up for SuperPlane](https://app.superplane.com/). Create or enter the workspace where you want to run your software factory. The onboarding flow guides you through creating your first workspace.

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/src/assets/setup_first.png" alt="SuperPlane onboarding screen with the Get started button" />
  <figcaption>Start the onboarding flow to connect your first repository.</figcaption>
</figure>

To create a workspace for another repository open the workspace switcher in the upper left corner. Select **Create new workspace**, connect GitHub and choose the repository.

<figure class="sp-media-figure sp-media-figure--compact not-content">
  <img src="https://docs-assets.superplane.com/src/assets/switch_workspace.png" alt="SuperPlane workspace switcher with Create new workspace" />
  <figcaption>Use the workspace switcher to open an existing workspace or create another one.</figcaption>
</figure>

Read [Build your first Factory](/get-started/build-first-factory) for a detailed configuration walkthrough.

## 2. Let SuperPlane prepare the workspace

Connect the repository through GitHub during onboarding. SuperPlane prepares the workspace and begins bringing work into the factory.

For GitHub Issues the onboarding flow imports recent open tickets and starts reviewing their suitability for agent execution. You do not need to copy tickets into SuperPlane.

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/src/assets/workspace_done.png" alt="SuperPlane onboarding completion screen showing imported GitHub tickets" />
  <figcaption>SuperPlane imports work from your repository and starts evaluating what the factory can take on.</figcaption>
</figure>

## 3. Open your factory board

Select **Go to your board**. The factory pipeline contains four stages:

<ol class="quickstart-stages not-content">
  <li><strong>Backlog</strong><span>Work is discovered and evaluated.</span></li>
  <li><strong>Implement</strong><span>An agent plans the task and changes the code.</span></li>
  <li><strong>Verify</strong><span>Checks and review feedback validate the result.</span></li>
  <li><strong>Done</strong><span>The pull request completes the factory workflow.</span></li>
</ol>

Focus on **Backlog** first. Newly discovered work appears here before implementation begins.

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/src/assets/final_done.png" alt="SuperPlane factory board with tasks waiting in Backlog" />
  <figcaption>The board shows discovered work and each task's current factory stage.</figcaption>
</figure>

## 4. Understand what happens next

When you start a task it moves through implementation and verification. A failed check can return the task to the agent with feedback. Work reaches Done when the completion rule is satisfied, such as attaching a pull request after every required status check passes.

<figure class="sp-media-figure not-content">
  <img src="https://docs-assets.superplane.com/src/assets/whats_next.png" alt="Factory flow from Backlog through Implement and Verify to a review ready pull request" />
  <figcaption>Verification can return failed work to the agent before the pull request reaches Done.</figcaption>
</figure>

Starting a task authorizes code work for that task. Review the title, description, repository and factory line before you confirm.

## Tips for your first run

- **Start small:** Choose a focused task with a defined expected outcome.
- **Add enough context:** Describe what should change, where it should change and what success looks like.
- **Choose the right repository:** Use one with a few open issues and existing tests or CI checks.
- **Use the defaults first:** Complete the first run before you change agents, automations or verification steps.
