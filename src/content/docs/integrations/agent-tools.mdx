---
title: Agent tools
description: Reference for the tools that SuperPlane gives coding agents during a run.
---

When SuperPlane starts a coding agent on a fleet runner, the agent gets a set of SuperPlane tools. The agent uses them to change the task it works on: owners, checks, artifacts, plans and screenshots.

## All tools

Every run gets these tools:

- [`list_members`](#list_members): List the people in the organization, with their roles.
- [`suggest_task_owners`](#suggest_task_owners): Find the people who can own or review the task.
- [`assign_task_owner`](#assign_task_owner): Set the owner of the task.
- [`list_tasks`](#list_tasks): List the tasks in the workspace.
- [`create_task`](#create_task): Create a draft task.
- [`close_task`](#close_task): Close the task.
- [`add_checks`](#add_checks): Add checks with a score and a reason to the task.
- [`remove_checks`](#remove_checks): Remove checks from the task.
- [`list_artifacts`](#list_artifacts): List the artifacts on the task.
- [`get_artifact`](#get_artifact): Read one artifact.
- [`add_artifact`](#add_artifact): Attach a markdown note, a link or a file to the task.
- [`remove_artifact`](#remove_artifact): Remove an artifact from the task.

Planning runs also get:

- [`propose_update`](#propose_update): Publish the plan scores, the specification and a survey.
- [`inspect_attachment`](#inspect_attachment): View an image that a person attached to the task.

Task runs also get these tools when the step turns them on:

- [`publish_link`](#publish_link): Attach a link to the task, for example a preview environment.
- [`inspect_screenshot`](#inspect_screenshot): View a screenshot before the upload.
- [`upload_screenshot`](#upload_screenshot): Upload a screenshot or a video to the task.
- [`report_visual_evidence_unavailable`](#report_visual_evidence_unavailable): Tell why the run could not capture screenshots.

Merge confidence runs also get:

- [`report_merge_check`](#report_merge_check): Publish one merge confidence check for the pull request.

## How access works

- Each run gets its own token. The agent sees only the tools that its run can use.
- A tool always acts on the task of the run.
- Each tool also has a `superplane task` command in the shell of the run. Run `superplane task --help` to see them.
- When a call fails, the agent gets the error, for example `title is required`. The agent can fix the input and try again.

## list_members

Lists the people in the organization.

**Input:** none.

**Output:** **members**, sorted by name. Each member has **user_id**, **name**, **email**, **github_login**, **roles** (for example `Owner`) and **open_tasks** (the draft and open tasks that the person owns in the workspace).

## suggest_task_owners

Finds the people who can own or review the task. Give it the paths that the change touches, and it ranks people by their recent commits on those paths.

Previous name: `suggest_owners`.

**Input:**

- **paths** (optional): Up to 10 files or directories in the repository, for example `pkg/payments`.

**Output:**

- **current_owners**: The current owners of the task.
- **code_owners**: People ranked by their commits on the paths, with **commits**, **last_commit_at** and **score**. Empty when you give no paths.
- **members**: All people who can own tasks, fewest open tasks first.
- **history_note**: A message when SuperPlane cannot read the code history. Then use **members**.

SuperPlane looks at the last 180 days of commits. Recent commits count more. Bot commits do not count. Only people with a linked GitHub account can be code owners.

## assign_task_owner

Sets one person as the owner of the task. That person replaces all current owners.

Previous name: `assign_owner`.

**Input:**

- **user** (required): A `user_id` or `github_login` from `list_members` or `suggest_task_owners`.
- **reason** (optional): One sentence that people see on the task, for example `You changed pkg/payments/charge.go 3 times this month.` Up to 280 characters.
- **only_if_unassigned** (optional): When `true`, do nothing if the task already has an owner.

**Output:** **status** is `assigned` with the new **owner**, or `kept` with the current **owners**.

A closed or archived task cannot change owners.

## list_tasks

Lists the tasks in the workspace, newest update first. Archived tasks are not listed.

**Input:**

- **state** (optional): `draft`, `open` or `closed`. Give one value or a list.
- **limit** (optional): 1 to 100. The default is 100.

**Output:** **tasks**. Each task has **id**, **key**, **title**, **state** and **url**.

## create_task

Creates a draft task in the workspace, with no owner.

**Input:**

- **title** (required): Up to 256 characters.
- **description** (optional): Up to 20000 characters.

**Output:** The new task with **id**, **key**, **title**, **state** and **url**.

## close_task

Closes the task. Other runs on the task stop.

**Input:**

- **result** (optional): `completed`, `rejected` or `failed`. The default is `completed`. A draft task can only be `rejected`.

**Output:** The closed task with **id**, **key**, **title**, **state**, **result** and **url**.

## add_checks

Adds checks to the task. A check shows a score and a reason on the task. Use it from any step to report your own checks.

**Input:**

- **checks** (required): A list of checks. Each check has:
  - **key**: A stable ID, for example `api-latency`. A check with the same key is replaced.
  - **name**: The label that people see, for example `API latency`.
  - **score** and **max_score**: For example `2` of `5`.
  - **level**: `positive`, `caution` or `critical`. It sets the color.
  - **reason**: One sentence that explains the score.

**Output:** **checks**, the saved checks.

## remove_checks

Removes checks from the task.

**Input:**

- **keys** (required): The keys of the checks to remove.

**Output:** **removed**, the keys that SuperPlane removed.

## list_artifacts

Lists the artifacts on the task, newest first, without their content.

**Input:**

- **type** (optional): `markdown`, `link` or `file`.

**Output:** **artifacts**. Each artifact has **id**, **key**, **type**, **title**, **url** and **created_at**.

## get_artifact

Reads one artifact and its content.

**Input:**

- **id** or **key** (one is required).

**Output:** The artifact, plus **body** for markdown, **url** for a link, or **public_url**, **content_type** and **size_bytes** for a file.

## add_artifact

Attaches a markdown note, a link or a file to the task.

**Input:**

- **type** (required): `markdown`, `link` or `file`.
- **body**: The markdown, for `markdown`.
- **url**: An `http` or `https` URL, for `link`.
- **path**: A file in the task directory, for `file`.
- **title** (optional): The label that people see.
- **key** (optional): A stable ID. An artifact with the same key is replaced. Without a key, each call adds a new artifact.

**Output:** The saved artifact with **artifact_id**, **type**, **title**, **key** and **url**.

## remove_artifact

Removes one artifact from the task.

**Input:**

- **key** or **title** (one is required). A title removes the newest artifact with that title and no key.

**Output:** **id** and **title** of the removed artifact.

## propose_update

Publishes the plan of a planning session. Give at least one of scores, spec or survey.

**Input:**

- **scores**: **clarity**, **complexity** and **verifiability**. Each is 1 to 3, with a one-sentence **summary**. The first call must include scores.
- **spec**: The full specification in markdown. It is saved as the `plan.md` artifact.
- **survey**: 1 to 5 questions for the person who plans the task. Each question has a **prompt**, up to 6 **options** and an optional **recommended_option**. There is no survey when all scores are 3.

**Output:** **status** is `shown`.

Each call replaces the previous spec and survey.

## inspect_attachment

Shows an image that a person attached to the task, so the agent can see it. Use it for every PNG, JPEG, GIF or WebP attachment.

**Input:**

- **path** (required): The image in the task attachments directory. Up to 70 MiB.

**Output:** The image, plus **filename**, **mimeType**, **sizeBytes** and **sha256**.

## publish_link

Attaches an `http` or `https` link to the task, for example a preview environment.

**Input:**

- **url** (required): The link.
- **title** (optional): The label that people see.
- **key** (optional): A stable ID. A link with the same key is replaced.

**Output:** **artifact_id**, **url**, **title** and **key**.

## inspect_screenshot

Shows a screenshot so the agent can check it before the upload. Use it for every screenshot before `upload_screenshot`.

**Input:**

- **path** (required): A PNG, JPEG or WebP file in the task `evidence/` directory. Up to 5 MiB.

**Output:** The image, plus **filename**, **mimeType**, **sizeBytes** and **sha256**.

## upload_screenshot

Uploads a screenshot or a video from the task `evidence/` directory and attaches it to the task. Inspect each screenshot first. If the file changes, inspect it again.

Previous name: `upload_artifact`.

**Input:**

- **path** (required): A `.png`, `.jpg`, `.jpeg`, `.webp`, `.webm` or `.mp4` file. Up to 100 MiB.
- **title** (optional): The label that people see. The default is the filename.
- **posterPath** (optional): For a video, an inspected image that the task shows in place of the video.

**Output:** **artifact_id**, **file_id**, **filename**, **content_type**, **size_bytes**, **public_url**, **title** and **markdown**, a snippet that shows the file in a pull request description.

## report_visual_evidence_unavailable

Tells why the run could not capture screenshots. Use it only after you try a preview environment and a Playwright capture.

**Input:**

- **reason** (required): Why there are no screenshots.
- **attempts** (required): What the agent tried. Each attempt has a **type** (`preview`, `playwright` or `upload`), the **command** and the **outcome**. Include at least one `preview` and one `playwright` attempt.

**Output:** **status** (`unavailable`, `partial` or `captured`), **reason**, **attempts** and the uploaded **artifacts**.

## report_merge_check

Publishes one merge confidence check for the pull request. Use it once, for the check that the step prompt names.

**Input:**

- **check** (required): The ID from the `Merge check:` line of the prompt, for example `risk`.
- **score** (required): 1 to 5.
- **summary** (required): One sentence. Do not repeat the score.

**Output:** **status** is `reported`.

The built-in checks are `risk` (Blast radius), `drift` (Drift from Specification), `performance`, `security` and `reversibility`. For `risk`, `drift` and custom checks, a lower score is better. For the others, a higher score is better. A new report for the same check replaces the score. The step must still be running.
