title: Agent tools

When SuperPlane starts a coding agent on a fleet runner (Claude Code, Codex, OpenRouter or a SuperPlane-hosted model), the agent gets the `superplane_global` Model Context Protocol (MCP) server. Its tools let the agent read and change the task it works on: owners, checks, artifacts, plans and visual evidence. This page is for people who write agent prompts and review agent runs.

import { CardGrid, LinkCard } from "@astrojs/starlight/components";

## How access works

- Each run gets its own token. The token decides which tools the agent can see.
- `tools/list` returns only the tools that the run can use. SuperPlane checks the token again on every call.
- A tool acts on the task of the run. On a planning run, that task is the draft of the planning session.
- Each tool also has a `superplane task` command in the run's shell. Run `superplane task --help` to see the commands.
- A failed call returns the error text as the tool result, for example `title is required`. The agent can fix the input and call the tool again.

## Tools by run

- **Every run**: the [people](#people), [task](#tasks) and [artifact](#artifacts) tools, plus `add_checks` and `remove_checks`.
- **Planning runs** also get `propose_update` and `inspect_attachment`.
- **Task runs** also get `publish_link` when the step publishes links, and the [visual evidence](#visual-evidence) tools when the step collects visual evidence.
- **Merge confidence runs** also get `report_merge_check`.

<a id="list_members"></a>

## list_members

Lists the human members of the organization. Use it to find a person by name, role or GitHub login.

### Input

This tool takes no input.

### Output

- **members**: One entry per member, sorted by name. Each entry has:
  - **user_id**: The SuperPlane user ID.
  - **name** and **email**: The name and email of the member.
  - **github_login**: The linked GitHub login. Empty when the member has no linked GitHub account.
  - **roles**: The organization roles of the member, for example `Owner` or `Admin`.
  - **open_tasks**: The number of draft and open tasks that the member owns in this workspace.

### Example output

```json
{
  "members": [
    {
      "user_id": "6f1c2a4e-8d3b-4c1a-9b7e-2f5d8a0c1e34",
      "name": "Ana Souza",
      "email": "ana@example.com",
      "github_login": "anasouza",
      "roles": ["Owner"],
      "open_tasks": 2
    }
  ]
}
```

<a id="suggest_task_owners"></a>

## suggest_task_owners

Finds the people who can own or review this task. Pass the repository paths that the change touches to rank members by their recent commits on those paths.

`suggest_owners` is the previous name of this tool. It takes the same input.

### Input

- **paths** (optional): Up to 10 repository-relative files or directories, most specific first, for example `pkg/payments` or `web_src/src/pages/checkout.tsx`. Empty paths and paths that contain `..` are ignored.

### Output

- **paths**: The paths that SuperPlane used.
- **current_owners**: The current owners of the task. Each entry has the same fields as a [`list_members`](#list_members) entry.
- **code_owners**: Members ranked by their recent commits on the paths. Empty when you pass no paths. Each entry has:
  - **user_id**, **name**, **github_login**, **roles** and **open_tasks**.
  - **commits**: The number of commits on the paths.
  - **last_commit_at**: The time of the latest commit.
  - **paths**: The paths that the member changed.
  - **score**: A ranking score. Recent commits count more.
- **members**: All members that can own tasks, fewest open tasks first.
- **history_note**: Empty, or a message when SuperPlane cannot read the code history. When it is set, use **members**.

### Notes

- Code history covers the last 180 days and up to 50 commits per path. A commit loses half its weight every 30 days.
- Only members with a linked GitHub account can appear in **code_owners**.
- Bot commits and commits from the SuperPlane agent do not count.

### Example output

```json
{
  "paths": ["pkg/payments"],
  "current_owners": [],
  "code_owners": [
    {
      "user_id": "6f1c2a4e-8d3b-4c1a-9b7e-2f5d8a0c1e34",
      "name": "Ana Souza",
      "github_login": "anasouza",
      "roles": ["Owner"],
      "commits": 3,
      "last_commit_at": "2026-10-28T14:02:11Z",
      "paths": ["pkg/payments"],
      "open_tasks": 2,
      "score": 2.71
    }
  ],
  "members": [],
  "history_note": ""
}
```

<a id="assign_task_owner"></a>

## assign_task_owner

Sets one person as the only owner of this task. The new owner replaces all current owners, including owners that a person assigned by hand.

`assign_owner` is the previous name of this tool. It takes the same input.

### Input

- **user** (required): A `user_id` or `github_login` from [`suggest_task_owners`](#suggest_task_owners) or [`list_members`](#list_members). A leading `@` is allowed.
- **reason** (optional): One sentence that SuperPlane shows on the task, for example `You changed pkg/payments/charge.go 3 times in the last 30 days.` SuperPlane removes links and keeps the first 280 characters.
- **only_if_unassigned** (optional): When `true`, keep the current owners if the task already has one.

### Output

- **status**: `assigned` when the person is now the owner. `kept` when **only_if_unassigned** is `true` and the task already had an owner.
- **owner**: The new owner, when **status** is `assigned`.
- **owners**: The current owners, when **status** is `kept`.

### Notes

- The person must be a member of the organization who can own tasks.
- A closed or archived task cannot change owners.

### Example output

```json
{
  "status": "assigned",
  "owner": {
    "user_id": "6f1c2a4e-8d3b-4c1a-9b7e-2f5d8a0c1e34",
    "name": "Ana Souza",
    "email": "ana@example.com",
    "github_login": "anasouza",
    "roles": ["Owner"],
    "open_tasks": 3
  }
}
```

<a id="list_tasks"></a>

## list_tasks

Lists tasks in this workspace, newest update first.

### Input

- **state** (optional): `draft`, `open` or `closed`. Pass one value or a list to combine them.
- **limit** (optional): The maximum number of tasks, from 1 to 100. The default is 100.

### Output

- **tasks**: One entry per task. Each entry has **id**, **key**, **title**, **state** and **url**.

### Notes

- Archived tasks are not listed.
- There is no offset. Use **state** to narrow the list.

### Example output

```json
{
  "tasks": [
    {
      "id": "0b9a7c52-3e1d-4f6a-8c2b-91d4e7a5f013",
      "key": "PAY-42",
      "title": "Retry failed refunds",
      "state": "open",
      "url": "https://app.superplane.com/your_org_id/workspaces/payments/task/42"
    }
  ]
}
```

<a id="create_task"></a>

## create_task

Creates a draft task in this workspace. The new task has no owner.

### Input

- **title** (required): Up to 256 characters.
- **description** (optional): Up to 20000 characters.

### Output

The new task with **id**, **key**, **title**, **state** and **url**. **state** is `draft`.

<a id="close_task"></a>

## close_task

Closes the task of this run. On a planning run, it closes the draft of the planning session.

### Input

- **result** (optional): `completed`, `rejected` or `failed`. The default is `completed`.

### Output

The closed task with **id**, **key**, **title**, **state**, **result** and **url**.

### Notes

- A draft task can only be `rejected`. An open task can be `completed`, `rejected` or `failed`.
- A closed or archived task cannot close again.
- Other runs on the task stop. The run that calls the tool continues.

<a id="add_checks"></a>

## add_checks

Adds checks to this task. A check shows a score and a reason on the task, like the scores of a plan or a merge confidence check. Use it from any step to report your own checks.

### Input

- **checks** (required): The list of checks. Each check has:
  - **key** (required): A stable ID for the check, for example `api-latency`. A check with the same key on this task is replaced.
  - **name** (required): The label that people see, for example `API latency`.
  - **score** (required): A number from 0 to **max_score**.
  - **max_score** (required): The highest possible score, for example `5`.
  - **level** (required): `positive`, `caution` or `critical`. It sets the color of the check.
  - **reason** (required): One sentence that explains the score.

### Output

- **checks**: The saved checks with **key**, **name**, **score**, **max_score** and **level**.

### Example output

```json
{
  "checks": [
    {
      "key": "api-latency",
      "name": "API latency",
      "score": 2,
      "max_score": 5,
      "level": "caution"
    }
  ]
}
```

<a id="remove_checks"></a>

## remove_checks

Removes checks from this task.

### Input

- **keys** (required): The keys of the checks to remove.

### Output

- **removed**: The keys that SuperPlane removed.

<a id="report_merge_check"></a>

## report_merge_check

Publishes one merge confidence check for the pull request of this task. Call it once for the check that the step prompt names.

### Input

- **check** (required): The ID from the `Merge check:` line of the prompt, for example `risk` or `api-latency`.
- **score** (required): An integer from 1 to 5.
- **summary** (required): One sentence. Do not repeat the score. Up to 1000 bytes.

### Output

- **status**: `reported`.

### Built-in checks

| ID | Name | Better score |
| --- | --- | --- |
| `risk` | Blast radius | Lower |
| `drift` | Drift from Specification | Lower |
| `performance` | Performance | Higher |
| `security` | Security | Higher |
| `reversibility` | Reversibility | Higher |

A custom check ID uses the step name as its label. A lower score is better.

### Notes

- The check must be on in this step. Other IDs return `merge confidence check is off`.
- The score sets the level. When lower is better, 1 or 2 is positive, 3 is caution and 4 or 5 is critical. When higher is better, 4 or 5 is positive, 3 is caution and 1 or 2 is critical.
- A second report for the same check replaces the score and keeps the previous score.
- The step must still be running. A report after the step ends fails.

<a id="propose_update"></a>

## propose_update

Publishes the plan of a planning session: scores, the specification and an optional survey. Pass at least one of them.

### Input

- **scores**: The three plan scores. Each score is an integer from 1 to 3 with a one-sentence **summary**:
  - **clarity**: The outcome, scope and done condition are defined.
  - **complexity**: One agent can finish the task in one run.
  - **verifiability**: Tests or checks can prove the change.
- **spec**: The full specification in markdown.
- **survey**: Questions for the person who plans the task. **questions** has 1 to 5 entries. Each entry has a **prompt**, up to 6 **options** and an optional **recommended_option** that matches one option exactly.

### Output

- **status**: `shown`.

### Notes

- The first call of a session must include **scores**.
- **scores** show as the Clarity score, Complexity and Verifiability checks on the draft task. A score of 3 is positive, 2 is caution and 1 is critical.
- **spec** is saved as the `plan.md` artifact. The next call replaces it.
- **survey** replaces the current survey. A survey is refused when all three scores are 3.

<a id="inspect_attachment"></a>

## inspect_attachment

Shows an image that a person attached to the task, so the agent can see it. Call it for every PNG, JPEG, GIF or WebP attachment. Do not use OCR or the `file` command.

### Input

- **path** (required): The path of the image in the task attachments directory. A relative path starts in that directory.

### Output

The image, plus **path**, **filename**, **mimeType**, **sizeBytes** and **sha256**.

### Notes

- The file must be inside the task attachments directory, up to 70 MiB.

<a id="list_artifacts"></a>

## list_artifacts

Lists the artifacts on this task, newest first. The list does not include content. Use [`get_artifact`](#get_artifact) to read one artifact.

### Input

- **type** (optional): `markdown`, `link` or `file`.

### Output

- **artifacts**: One entry per artifact. Each entry has **id**, **key**, **type**, **title**, **url** and **created_at**.

### Example output

```json
{
  "artifacts": [
    {
      "id": "c3e8a1f0-5b2d-4e7c-9a6f-0d1b2c3e4f50",
      "key": "staging",
      "type": "link",
      "title": "Staging",
      "url": "https://staging.example.com/pr-42",
      "created_at": "2026-10-30T18:21:07Z"
    }
  ]
}
```

<a id="get_artifact"></a>

## get_artifact

Reads one artifact on this task and its content.

### Input

- **id** or **key** (one is required): The artifact from [`list_artifacts`](#list_artifacts).

### Output

The fields from `list_artifacts`, plus the content:

- **body**: The markdown, for a `markdown` artifact.
- **url**: The link, for a `link` artifact.
- **public_url**, **content_type** and **size_bytes**: The file, for a `file` artifact.

<a id="add_artifact"></a>

## add_artifact

Attaches an artifact to this task: a markdown note, a link or a file.

### Input

- **type** (required): `markdown`, `link` or `file`.
- **title** (optional): The label that people see. Up to 1024 characters.
- **key** (optional): A stable ID, up to 512 bytes. An artifact with the same key on this task is replaced. Without a key, each call adds a new artifact.
- **body**: The markdown. Required when **type** is `markdown`.
- **url**: An `http` or `https` URL. Required when **type** is `link`.
- **path**: The path of a file in the task directory. Required when **type** is `file`.

### Output

The saved artifact with **artifact_id**, **type**, **title**, **key** and **url**.

<a id="publish_link"></a>

## publish_link

Attaches an `http` or `https` link to this task, for example a preview environment.

### Input

- **url** (required): An `http` or `https` URL.
- **title** (optional): The label that people see.
- **key** (optional): A stable ID. A later call with the same key replaces the link.

### Output

**artifact_id**, **url**, **title** and **key**.

<a id="remove_artifact"></a>

## remove_artifact

Removes one artifact from this task. On a planning run, it changes the draft of the planning session.

### Input

- **key** or **title** (one is required): A key selects that artifact. A title selects the newest artifact with that title and no key. Keys are up to 512 bytes and titles up to 1024 characters.

### Output

**id** and **title** of the removed artifact.

### Notes

- A closed or archived task cannot change.

<a id="inspect_screenshot"></a>

## inspect_screenshot

Shows a screenshot before upload, so the agent can check it. Call it for every screenshot before [`upload_screenshot`](#upload_screenshot).

### Input

- **path** (required): The path of a PNG, JPEG or WebP file in the task `evidence/` directory, up to 5 MiB.

### Output

The image, plus **path**, **filename**, **mimeType**, **sizeBytes** and **sha256**.

### Notes

- SuperPlane records the size and hash of the inspected file.
- A screenshot that is larger than 5 MiB fails. Capture a smaller or more focused image.

<a id="upload_screenshot"></a>

## upload_screenshot

Uploads a screenshot or video from the task `evidence/` directory and attaches it to the task.

`upload_artifact` is the previous name of this tool. It takes the same input.

### Input

- **path** (required): A `.png`, `.jpg`, `.jpeg`, `.webp`, `.webm` or `.mp4` file in the task `evidence/` directory, up to 100 MiB.
- **title** (optional): The label that people see. The default is the filename.
- **posterPath** (optional): For a video only. An inspected PNG, JPEG or WebP image that the task shows in place of the video.

### Output

- **artifact_id** and **file_id**: The IDs of the new artifact and file.
- **filename**, **content_type** and **size_bytes**: The uploaded file.
- **public_url**: The URL of the file.
- **title**: The label of the artifact.
- **markdown**: A markdown snippet that shows the file, for example in a pull request description.

### Notes

- Inspect each screenshot with [`inspect_screenshot`](#inspect_screenshot) first. If the file changes after the inspection, inspect it again.
- With **posterPath**, SuperPlane uploads the poster and then the video. **markdown** shows the poster as a link to the video.

### Example output

```json
{
  "artifact_id": "8a2d4f6b-1c3e-4a5b-9d7f-e0c1b2a3d4e5",
  "file_id": "f1e2d3c4-b5a6-4978-8a9b-0c1d2e3f4a5b",
  "filename": "checkout.png",
  "content_type": "image/png",
  "size_bytes": 184233,
  "public_url": "https://app.superplane.com/api/v1/public/artifacts/2b7e9c1d-4a3f-4e8b-a1c5-d6f7e8a9b0c1/checkout.png",
  "title": "Checkout page",
  "markdown": "![Checkout page](https://app.superplane.com/api/v1/public/artifacts/2b7e9c1d-4a3f-4e8b-a1c5-d6f7e8a9b0c1/checkout.png)"
}
```

<a id="report_visual_evidence_unavailable"></a>

## report_visual_evidence_unavailable

Records why the run could not capture the required visual evidence. Call it only after you try an isolated preview and a Playwright capture.

### Input

- **reason** (required): Why the evidence is not available.
- **attempts** (required): What the agent tried. Include at least one `preview` attempt and one `playwright` attempt. Add an `upload` attempt when an upload failed. Each attempt has:
  - **type**: `preview`, `playwright` or `upload`.
  - **command**: The command that the agent ran.
  - **outcome**: What happened.

### Output

- **status**: `unavailable` when nothing was uploaded. `captured` or `partial` when some files were uploaded.
- **reason** and **attempts**: The recorded input.
- **artifacts**: The files that the run uploaded.
