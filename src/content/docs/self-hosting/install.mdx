---
title: Install SuperPlane
description: Install SuperPlane on AWS, Azure, or Google Cloud with Terraform, then create the owner account and install Fleet Manager.
---

import { Aside, Steps, Tabs, TabItem } from "@astrojs/starlight/components";

Install SuperPlane from published images. Terraform creates the cluster. You create the owner account in the browser, then run the Fleet Manager commands the product prints.

Select **AWS**, **Azure**, or **Google Cloud** once. The tabs on this page stay in sync. Plan for 45 minutes. You need a domain you control, such as `superplane.example.com`.

## 1. Sign in

Install Terraform 1.5 or later, kubectl, Helm 3.12 or later, and git.

<Tabs syncKey="cloud">
  <TabItem label="AWS">

Install the [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html). The account must be able to create EKS, VPC, RDS, S3, EFS, IAM, and EC2 resources.

```bash
export AWS_PROFILE=your_aws_profile
aws sts get-caller-identity
```

Terraform cannot use an `aws login` source profile to assume a role, but the AWS CLI can. When `terraform plan` reports `failed to load assume role`, export the credentials and clear the profile:

```bash
eval "$(aws configure export-credentials --profile your_aws_profile --format env)"
unset AWS_PROFILE
aws sts get-caller-identity
```

Clear `AWS_PROFILE` so Terraform uses the exported credentials. Run the export again when those credentials expire.

  </TabItem>
  <TabItem label="Azure">

Install the [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli). You need Owner on the subscription, or Contributor plus User Access Administrator.

```bash
az login
az account set --subscription your_subscription_id
az account show --query id -o tsv
```

  </TabItem>
  <TabItem label="Google Cloud">

Install the [gcloud CLI](https://cloud.google.com/sdk/docs/install). You need Owner on the project, and billing must be on. Terraform uses application-default credentials.

```bash
export PROJECT_ID=your_gcp_project
gcloud auth login
gcloud auth application-default login
gcloud config set project "$PROJECT_ID"
```

  </TabItem>
</Tabs>

## 2. Prepare the account

<Tabs syncKey="cloud">
  <TabItem label="AWS">

Use `us-east-1`. Copy the newest public AMI for each architecture into `terraform.tfvars`:

```bash
aws ec2 describe-images \
  --region us-east-1 \
  --owners 802589444644 \
  --filters 'Name=name,Values=superplane-runner-*' 'Name=is-public,Values=true' \
  --query 'sort_by(Images,&CreationDate)[].[Architecture,ImageId,CreationDate]' \
  --output table
```

  </TabItem>
  <TabItem label="Azure">

Register the resource providers once per subscription:

```bash
for p in Microsoft.ContainerService Microsoft.Compute \
  Microsoft.Network Microsoft.Storage Microsoft.DBforPostgreSQL; do
  az provider register --namespace "$p"
done
```

Stay in `eastus` with `runner_zones = ["1"]` unless you need another region. `eastus` and `westus3` have both architectures. In `eastus`, arm64 is not offered in zone 2.

| Region | amd64 (`Standard_D2ds_v4`) | arm64 (`Standard_D2pds_v6`) |
| --- | --- | --- |
| eastus | zones 1, 2, 3 | zones 1, 3 |
| centralus | not offered | zones 1, 2, 3 |
| westus2 | not offered | zone 1 |
| westus3 | zones 1, 2, 3 | zones 1, 2, 3 |

If this command prints no SKUs, set `create_postgresql_flexible_server = false` before the first apply. PostgreSQL then runs in the cluster.

```bash
az postgres flexible-server list-skus --location eastus -o table
```

  </TabItem>
  <TabItem label="Google Cloud">

Create the address and the DNS record before Terraform. Let's Encrypt checks public DNS during the apply.

```bash
gcloud services enable compute.googleapis.com iam.googleapis.com --project="$PROJECT_ID"
gcloud compute addresses create superplane-ip --global --ip-version=IPV4
gcloud compute addresses describe superplane-ip --global --format='get(address)'
```

Create an A record from your domain to that address.

```bash
dig +short superplane.example.com @8.8.8.8
```

The answer must be the static IP. Public runner images are not published yet. Leave the runner image variables empty and skip Fleet Manager in step 8.

  </TabItem>
</Tabs>

## 3. Set the Terraform variables

```bash
git clone https://github.com/superplanehq/superplane.git
cd superplane
```

<Tabs syncKey="cloud">
  <TabItem label="AWS">

```bash
cd release/terraform/eks
cp terraform.tfvars.example terraform.tfvars
```

```hcl
domain_name              = "superplane.example.com"
letsencrypt_email        = "you@example.com"
region                   = "us-east-1"
runner_image_amd64       = "latest_amd64_ami"
runner_image_arm64       = "latest_arm64_ami"
superplane_chart_version = "@@SUPERPLANE_CHART_VERSION@@"
```

Use the AMI IDs from the command above. `x86_64` is amd64. Leave `superplane_image_tag` and `helm_chart_path` empty. The chart version has no `v` prefix. An empty image tag selects the image for that chart. An empty AMI disables that architecture in the fleet wizard.

  </TabItem>
  <TabItem label="Azure">

```bash
cd release/terraform/aks
cp terraform.tfvars.example terraform.tfvars
```

```hcl
subscription_id          = "your_subscription_id"
domain_name              = "superplane.example.com"
letsencrypt_email        = "you@example.com"
location                 = "eastus"
runner_zones             = ["1"]
superplane_chart_version = "@@SUPERPLANE_CHART_VERSION@@"
```

Leave `superplane_image_tag`, `runner_image_amd64`, `runner_image_arm64`, and `helm_chart_path` empty. The chart version has no `v` prefix. An empty image tag selects the image for that chart.

  </TabItem>
  <TabItem label="Google Cloud">

```bash
cd release/terraform/gke
cp terraform.tfvars.example terraform.tfvars
```

```hcl
project_id               = "your_gcp_project"
domain_name              = "superplane.example.com"
static_ip_name           = "superplane-ip"
letsencrypt_email        = "you@example.com"
superplane_chart_version = "@@SUPERPLANE_CHART_VERSION@@"
```

Leave `superplane_image_tag` and `superplane_chart_path` empty. The chart version has no `v` prefix. An empty image tag selects the image for that chart. A plain commit SHA in `superplane_image_tag` loads the UI from `assets.superplane.com`, and the browser blocks it on your domain. Keep `machine_type` at `e2-standard-2` or larger.

  </TabItem>
</Tabs>

<Aside type="caution">
Do not commit `terraform.tfvars`.
</Aside>

## 4. Apply

```bash
terraform init
terraform plan -out tfplan
terraform apply tfplan
```

<Aside type="caution">
Read the plan before you apply it. `terraform apply tfplan` does not ask again. The plan file can contain secrets. Do not commit `tfplan`.
</Aside>

The apply takes 15–25 minutes. On Google Cloud it also waits for the certificate, which can add about 15 minutes.

## 5. Connect kubectl

```bash
terraform output -raw kubectl_config_command
```

Run the printed command.

<Tabs syncKey="cloud">
  <TabItem label="AWS">

The command updates kubeconfig for the EKS cluster.

  </TabItem>
  <TabItem label="Azure">

Add `--overwrite-existing` so an older cluster named `superplane` does not block the update:

```bash
az aks get-credentials \
  --resource-group superplane \
  --name superplane \
  --admin \
  --overwrite-existing
```

  </TabItem>
  <TabItem label="Google Cloud">

The command gets credentials for zone `us-central1-a` unless you changed `zone`.

  </TabItem>
</Tabs>

```bash
kubectl get nodes
```

Every node is `Ready`.

## 6. Point DNS at SuperPlane

<Tabs syncKey="cloud">
  <TabItem label="AWS">

```bash
kubectl get svc -n traefik traefik \
  -o jsonpath='{.status.loadBalancer.ingress[0].hostname}'
```

Create a CNAME from your domain to that hostname.

  </TabItem>
  <TabItem label="Azure">

```bash
kubectl get svc -n ingress-nginx ingress-nginx-controller \
  -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
```

Create an A record from your domain to that IP.

  </TabItem>
  <TabItem label="Google Cloud">

The A record already exists. Confirm it still matches the static IP:

```bash
dig +short superplane.example.com @8.8.8.8
```

  </TabItem>
</Tabs>

An entry in `/etc/hosts` does not issue the certificate. Wait until the certificate is ready. AWS and Azure usually take 5–10 minutes. Google Cloud can take 15.

```bash
kubectl get certificate -n superplane
kubectl get pods -n superplane
```

The certificate is `Ready`, and every pod is `Running`.

## 7. Create the owner account

```bash
terraform output -raw superplane_url
```

SuperPlane creates an organization named Demo for this account.

<Steps>

1. On **Create the owner account**, enter the name, email, and password. The password needs 8 or more characters, one number, and one capital letter. Select **Continue**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/owner-account.webp" alt="Create the owner account form" />
     <figcaption>Create the owner account. This screen is the same on every cloud.</figcaption>
   </figure>

2. On **Choose an edition**, select **Continue with Community**. Select **Enterprise** only when you have a license file or a license key.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/edition.webp" alt="Choose an edition with Community selected" />
   </figure>

3. On **Send email from this installation**, select **Skip for now**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/smtp.webp" alt="SMTP form with Skip for now" />
   </figure>

</Steps>

## 8. Install Fleet Manager

On Google Cloud, select **Skip for now**. Come back when the public runner images are published. You can open this wizard later at **Fleet setup** (`/admin/fleet-manager-setup`).

<Steps>

1. On **Set up runner fleets**, select **Set up fleets**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/fleet-intro.webp" alt="Set up runner fleets" />
   </figure>

2. On **Choose a cloud provider**, select the provider Terraform loaded, then select **Continue**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/fleet-provider.webp" alt="Choose a cloud provider" />
   </figure>

3. On **Configure the default fleet**, keep `e1-large-amd64`. **Warm capacity** `0` starts a machine when a task arrives. **Maximum capacity** `1` is one machine. Each AWS or Azure machine uses 2 vCPUs. Select **Generate install command**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/fleet-configure.webp" alt="Configure the default fleet" />
     <figcaption>The machine type list follows the provider. Capacity is the same on every cloud.</figcaption>
   </figure>

4. On **Create the chart values**, copy the command and run it. It writes `fleet-manager-values.yaml`. Select **Continue**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/fleet-values.webp" alt="Create the chart values" />
   </figure>

5. On **Install the chart**, run the Helm command in the same directory. When the page says Fleet Manager created the selected fleets, select **Finish installation**.

   <figure class="sp-media-figure not-content">
     <img src="https://docs-assets.superplane.com/images/self-hosting/fleet-verified.webp" alt="Install the chart with Finish installation" />
   </figure>

</Steps>

<Aside type="caution">
`fleet-manager-values.yaml` contains an admin token. Do not commit it or send it to anyone.
</Aside>

<Tabs syncKey="cloud">
  <TabItem label="AWS">

The machine type is `m8a.large` for amd64 and `m8g.large` for arm64. If the file contains `<RUNNER_IMAGE>`, the AMI was empty at apply time. Set it, run `terraform apply` again, and reload the wizard.

  </TabItem>
  <TabItem label="Azure">

The amd64 size is `Standard_D2ds_v4`. For arm64, set `vmSize` to `Standard_D2pds_v6`. A `v5` size fails Trusted Launch. If the file contains `<AZURE_ZONE>`, set `zones` to the same list as `runner_zones`, then run Helm.

  </TabItem>
  <TabItem label="Google Cloud">

Skip Fleet Manager until a runner image is published. The wizard disables a fleet whose image is empty.

  </TabItem>
</Tabs>

## 9. Next

Start a task on the default fleet. With warm capacity at `0`, the first task waits while the machine boots. The [quickstart](/get-started/quickstart) connects a repository. Use your installation URL.

When something fails, use [Troubleshooting](/self-hosting/troubleshooting). To move to a newer chart or remove the stack, use [Upgrade and uninstall](/self-hosting/upgrade-and-uninstall).
